# Подготовка к защите

## Трассировка двух шагов

1. Откройте `TreeVisitor.evaluate`: из стека извлекается `Element`, вызывается `accept(this)`.
2. Покажите `FileNode.accept`: динамический тип элемента привёл именно в этот метод.
3. `visitor.visit(this)` выбирает перегрузку для `FileNode`, потому что статический тип `this` здесь `FileNode`.
4. `TreeVisitor.visit(FileNode)` вызывает `onFile`, а `TotalSizeVisitor.onFile` прибавляет размер.
5. В каталоге выбирается другая перегрузка; общий посетитель добавляет детей в стек.

Java выбирает перегрузку по типам на этапе компиляции, а реализацию виртуального
метода - по объекту во время выполнения. Visitor связывает эти механизмы.

## Демонстрация без IDE

```sh
mvn test
mvn package
java -jar target/visitor-pattern-1.0.0.jar
java -jar target/visitor-pattern-1.0.0.jar .txt 400
java -jar target/visitor-pattern-1.0.0.jar .txt 401
java -jar target/visitor-pattern-1.0.0.jar .png 1000
```

При `.txt 400` остаются `architecture.txt` и `old-notes.txt`; при `.txt 401` - только
`architecture.txt`. Так видна включительная граница. Общая сумма остаётся 3568.
Чтобы изменить данные, поменяйте размер одного файла в `Demo.sampleTree`, пересоберите
и сначала вручную предскажите новую сумму. Изменение демонстрации требует обновить
ожидания `DemoTest`; отдельные тесты операций имеют свои fixtures.

## Вопросы, которые нужно понимать

- Почему новый посетитель не требует изменения элементов? Контракт уже умеет оба типа;
  новый класс задаёт только обработку файлов/каталогов и результат.
- Что если добавить `LinkNode`? Потребуются новая перегрузка и правила обхода ссылки;
  иначе непонятно, считать цель повторно и как не допустить цикл.
- Кто отвечает за обход? Только `TreeVisitor`; `accept` не проходит по детям.
- Почему нельзя просто вызвать `visitor.visit(element)`? В `Visitor` нет `visit(Element)`;
  тип ссылки `Element` сам по себе не выбирает перегрузку конкретного узла.
- Почему статистика считает пустой каталог? Он тоже узел и имеет глубину, даже без файлов.
- Почему результаты не накапливаются? Каждый `evaluate` начинает с `reset`, `finally`
  очищает стек и контекст даже после ошибки.
- Что защищает дерево? Единый публичный `add`, неизменяемые имена, sealed типы,
  проверка родителя и цепочки предков, неизменяемый snapshot детей.
- Как работает путь от подкаталога? Контекст создаётся заново с `.` и глубиной 0;
  родительские ссылки не используются для построения результата поиска.

На защите стоит уметь объяснить `assertThrows` в `TreeIntegrityTest`, граничное
значение в `SearchVisitorTest` и подсчёт глубины в `StatisticsVisitorTest`.
